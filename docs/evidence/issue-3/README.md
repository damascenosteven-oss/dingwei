### 长测中发现的计时问题

首次长测中，Windows 采证端连接 ADB 时报 10055，第四段路线中断。没有计入该时段。单独检查此后 00:19–02:54 的数据库，仍有 310 条新记录，相邻收点最长间隔 30.104 秒。[中断记录](soak-interruption.json)

第二次长测中，有一段移动的服务器最长收点间隔为 30.067 秒，但 61 个不同采集时间中有 12 个晚于服务器收点时间，原计算得到 80.33%，该段失败。随后同时读取 AVD 与 PostgreSQL 时钟，实测 AVD 快约 1.1 秒。[原时钟计算的失败结果](clock-difference-failed.json)

补测在每个锁屏移动窗口使用 60 个不同速度的合成路线段，每段 30 秒。各段速度间隔 4 厘米/秒，允许模拟器系统输出经量化的 1 厘米/秒误差，邻段互不重叠。观察器在系统 GPS 输入之前以及独立查询确认该设备的新点已入库之后读取同一个单调时钟。由此得到采集到入库耗时的保守上限。采集时间不在相应时段或找不到来源的点计入分母且不算达标。原始采集和入库时间照常保留。这些逻辑均在验收程序内，设备应用、服务器和正式过滤保持原版本。

完整 30 分钟复测中，60 个不同时间的点全部匹配，最慢耗时上限 25.047 秒。两端直接相减时 60 个点全部为负。[统计](moving-monotonic.json) · [来源与入库观测](moving-timing-evidence.json) · [Android 定位时间说明](https://developer.android.com/reference/android/location/Location#getTime())

### 复查要点

- Android 定位 SDK 对本路线返回 GCJ02，精度示例为 5 米，模拟标记为 false。样本来源始终是系统模拟 GPS。接口回归另测带模拟标记的点可以形成传输回执，但家庭最新位置不能使用它。
- 家人小程序在微信开发者工具游客项目上运行，本次使用本机测试家庭会话。腾讯地图个别资源请求曾出现连接关闭，实图保留了实际显示的底图、定位标记和时间。
- 系统强停时 Android 无法执行程序。再次打开后，应用根据系统停止记录撤销之前的同意并通知服务器。在此之前家人端只能依据原采集时间判断位置是否过期。Android 10 无法用本实现区分强停与普通冷启动，采取重新征求同意的处理，本轮只在 API 36 实测。
- 这些记录的适用范围是该镜像和测试环境。vivo / iQOO 的 OriginOS、真实 GPS 和耗电需要在具体手机上测量。
