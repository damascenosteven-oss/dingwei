# 家人位置

家属通过微信小程序查看老人手机最后一次上报的位置。第一阶段交付家人首页：首次进入显示“尚未绑定老人设备”。定位采集、设备绑定和地图属于后续阶段。

## 打开首页

1. 使用本分支的源码。在微信开发者工具选择「小程序 → 导入」。
2. 选择包含 `project.config.json` 的仓库根目录。配置中的 `touristappid` 用于本地体验。无需安装 npm 依赖。
3. 点击「编译」，查看模拟器中的「家人位置」首页和未绑定提示。

## 本地检查与 CI

安装 Node.js 24，在仓库根目录运行：

```sh
node --test checks/home.test.mjs
```

GitHub Actions 在分支推送和拉取请求时运行同一命令。检查覆盖项目配置、应用入口、首页注册、页面文件和未绑定提示。模拟器显示与真机后台定位分别验收。

**我跑过｜故障验证。** 将首页注册列表临时置空后，上述命令退出码为 1，提示“首个注册页面必须是家人首页”。恢复原始配置后退出码为 0，3 项通过。远端记录见 [GitHub Actions](https://github.com/damascenosteven-oss/dingwei/actions/workflows/check.yml)。

## 分步路线和验收

| 阶段 | 操作 | 验收依据 |
| --- | --- | --- |
| 1 · 家人首页 | 导入仓库，编译首页，在本地和分支 CI 运行检查 | 模拟器显示“尚未绑定老人设备”；故意移除注册后检查失败，恢复后通过。 |
| 2 · 现有安卓手机锁屏测试 | 用参考项目记录手机型号、系统版本、初始设置和电量。本人授权后，先验证亮屏基线，再关闭微信、锁屏外出。覆盖静置、移动网络切换、断网恢复，持续携带 24 小时。 | 对照手机采集时间、服务端接收时间和家人页面显示时间。初始目标为联网室外移动时至少 90% 的相邻采集间隔在 90 秒内，联网静置最长间隔不超过 10 分钟。记录断更环节、实际间隔和耗电；未达标时先复测断更原因。 |
| 3 · 一个家庭的真实位置 | 老人同意共享，绑定家属，从手机上传一个新点，在另一部家属手机查看。 | 核对同一定位点的采集时间；验证其他家庭无法访问、老人停止共享后新的位置不再共享。 |
| 4 · 位置时效 | 展示最后采集时间，复现超过 10 分钟无新点、刷新和断网补传。 | 过期位置有提示，刷新保持原采集时间；补传旧点不能覆盖较新的位置。 |
| 5 · 家庭试用 | 在实际老人手机和家属手机上走通出门、查看、断网、恢复共享流程。 | 留存脱敏的型号、必要设置、更新间隔、全天耗电和已知限制，作为该机型的验收结果。 |
